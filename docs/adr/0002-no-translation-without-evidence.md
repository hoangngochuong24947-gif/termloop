# 没有证据就不产生译名

## Status

accepted

## 背景

这个项目最大的敌人不是记不住，是**记错**。实测 261 条存量词表里，随手抽查就发现至少两处「看起来完全正常、实际是错的」译名：

- `state population` 被译成「状态布居**阈值**」——英文里根本没有 threshold，凭空多出一个词
- `asymptotic limit` 被译成「渐近**边界**」——limit 是极限，不是边界

这类错误人眼扫过去会直接背下来，且事后极难发现。它们的共同点不是「翻译得不好」，而是**中文侧看起来像译名**。

## 决定

中文译名（`name`）的生成必须凭证据，证据分四级：

| 等级 | 含义 | 可否作 name |
|---|---|---|
| `unverified` | 尚未核查 | 可以，但界面标记，进审计待办 |
| `A` | 原始出处明确使用（论文 / 源码 / 规范 + locator） | 可以 |
| `B` | 权威中文术语源（名词委 / 术语在线 / 国标 / 权威译著） | 可以 |
| `C` | 已核查，确无权威来源 | **禁止**，只能写进 `explain` |

**`unverified` 与 `C` 必须是两个状态。** 合并成一个会让规则失效：要么把全部存量译名判死，要么被静默忽略。

## 考虑过的方案

- **只留两态（有证据 / 无证据）**：无法表达「还没有人去查过」这个绝大多数条目的真实状态。
- **让 LLM 直接判断译名可靠性**：不可审计、不可复现，且 LLM 恰恰是伪造译名的主要来源。
- **全部要求 A/B 才能入库**：会让 261 条存量一夜清零，在还没有验证产品价值时把路堵死。

## 后果

- 每条 Surface 都携带 evidence，API 强制要求写入方声明（缺省即 `unverified`，不得缺省为 A）。
- 「低证据条目不生成 zh2en 卡」成为卡片生成规则的一部分，而不是一句提示语。
- 审计（audit）从「锦上添花的功能」升级为一等能力：它是把 `unverified` 变成 `A/B/C` 的唯一手段。
